## Project

ByteFin is a personal finance web app for subdividing one bank account into multiple "funds" (e.g. Savings, Groceries, Rent) and tracking transactions within each. Built with Next.js (App Router), TailwindCSS, and Shadcn UI, backed by Convex. Primarily used on mobile, but supports desktop too.

## Commands

- `pnpm dev` — start the dev server
- `pnpm build` — production build
- `pnpm lint` — Biome check (lint)
- `pnpm format` — Biome format (writes changes)
- `npx convex dev` — push Convex functions/schema to your dev deployment and regenerate `convex/_generated`

There is no test suite configured in this repo.

## Architecture

### Module structure

Code under `src/modules/` is organized by feature, not by file type. Each module follows the same internal shape:

```
modules/<feature>/
  components/   # React components, each re-exported from index.ts
  hooks/        # feature hooks, each re-exported from index.ts
  forms/        # zod schemas for react-hook-form, re-exported from index.ts
  interfaces/   # TypeScript types for the feature
```

Forms use `react-hook-form` with `zod` schemas via `@hookform/resolvers`.

`src/modules/shared/` holds cross-cutting pieces: `ui/` (Shadcn primitives), generic `components/`, `hooks/`, `utils/`, and `localization/`.

Always import from a module's `index.ts` barrel (e.g. `@/modules/funds/hooks`, `@/modules/shared/ui`) rather than reaching into individual files — every component/hook/form directory exports through one. When adding a new component, hook, or schema, add its export to the relevant `index.ts`.

Path aliases (`tsconfig.json`): `@/*` → `src/*`, `@convex/*` → `convex/*`.

### Data layer (Convex)

`convex/*.ts` defines queries and mutations (e.g. `convex/funds.ts`, `convex/accounts.ts`); `convex/_generated/` is generated by the Convex CLI and imported via `@convex/_generated/api` and `@convex/_generated/dataModel`. The client is wired up once in `src/app/providers.tsx` via `ConvexProvider`.

Data flow: a feature hook (e.g. `useFunds`, `useAccounts` in `src/modules/funds/hooks/`) wraps `useQuery`/`useMutation` from `convex/react` and exposes handler functions to components — components never call Convex directly. There is one shared `accounts` document that funds allocate balance from; mutating a fund's balance and the account's balance are separate calls (`updateFundBalance`, `updateAccountBalance`) and must be kept in sync by the caller — see `getNewBalance` in `src/modules/shared/utils/utils.ts`, which both `convex/funds.ts` and `convex/accounts.ts` import for consistent balance math.

There is no `convex/schema.ts` — table shapes for `accounts` and `funds` are inferred from `ctx.db.insert`/`patch` calls, not a declared schema.

`AddTransactionDialog` builds its validation schema dynamically per transaction type (deposit vs. withdraw) via `addTransactionSchema(t, getContext)`; withdrawals are validated against the fund's current balance.

### Auth

Auth is a PIN check, not a real session/user system. `POST /api/validate-pin` (`src/app/api/validate-pin/route.ts`) compares the submitted PIN against `NEXT_LOGIN_PIN` (server env var) and returns `{ valid }`. On success, `useAuth` (`src/modules/authentication/hooks/useAuth.ts`) stores an `isAuthenticated` flag in `sessionStorage` — there is no server-side session, cookie, or middleware guarding routes; page-level components check `useAuth().isAuthenticated` and redirect to `/login` themselves.

### Localization

`src/modules/shared/localization/en.json` is the source of truth for UI strings. `useLocalization`'s `t()` takes dot-delimited keys typed via a `NestedKey<typeof enLocale>` mapped type derived directly from the JSON structure — adding a key to the JSON automatically updates the allowed key type, no manual type edits needed.

### Env vars

`NEXT_PUBLIC_CONVEX_URL`, `CONVEX_DEPLOYMENT`, `NEXT_LOGIN_PIN` (see `.env.local`, not committed).
